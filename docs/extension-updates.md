# Extension updates

The Settings editor's Version category shows the installed product version and the actual Extension Host machine/platform. It remains usable when the DSH connection is unavailable. The selected update channel is the only updater preference stored in VS Code global state; Webview restore stores category/scroll only, never a downloadable candidate.

## Explicit lifecycle

- **Check for Updates** reads the public GitHub `master-build` prerelease or latest stable release. No model, wrapper, DSH or GitHub credentials are used, and there is no background update polling.
- **Install update and restart** is offered only for a strictly newer version on a supported production Linux x64 Extension Host. Development Hosts, source version `0.0.0`, unsupported platforms and ambiguous remote execution overrides cannot install. Stable releases older than an installed master build are not offered as downgrades.
- Installation asks for modal consent naming the version, download size and target. It warns users to finish Agent, Tool and background work in **all** windows because a changed Runtime can replace the shared backend. This is user-confirmed maintenance, not an authoritative DSH idle check.
- The selected release is fetched again after consent. Version, source commit, asset id, size and checksum must still match; moving master builds require a new check rather than silently installing a different build.
- A host-wide kernel-owned loopback claim serializes competing windows and is retained until the install command settles, even if Settings closes. Process death releases the claim without stale-file recovery. The private port is derived from the product-data namespace; an unrelated collision fails closed rather than allowing concurrent installation.
- Download is streamed into a private temporary file with HTTPS authority/redirect restrictions, metadata/time/byte caps, SHA-256, size and checksum-manifest validation. GitHub release checksums protect transport/integrity, not against compromise of the repository/publisher; these are not Marketplace-signed packages.
- The ZIP directory is bounded and rejects unsafe paths, duplicate names, encryption and symlinks. Both the package manifest and embedded VSIX identity must match Companion/version/Linux x64. The package must remain solely workspace-executed and cannot contain localization or extension-pack routing changes.
- Only after verification does the host invoke `workbench.extensions.installExtension` with a **VS Code URI object**. Temporary data and the lock are removed before `workbench.action.reloadWindow`. User-facing wording says **restart**, not reload. Failed/cancelled installation never restarts; a restart failure after installation asks the user to restart manually.

## Local and Remote-SSH

Companion is a workspace extension. Downloads use a private `mkdtemp` directory under the Node Extension Host's OS temporary directory. The scheme of `globalStorageUri` is not a filesystem capability check: remote and provider-backed storage URIs must not disable host-local downloads or be interpreted as local paths. VS Code chooses the appropriate installation server from its verified manifest. Passing an actual URI object lets command RPC translate an Extension Host-local `file:` URI to the remote authority; passing a path string would instead invoke the Marketplace-ID branch and is not supported. `remote.extensionKind` overrides are checked again immediately before installation to avoid changing the target after consent.

The installed VS Code command handler awaits the VSIX installation and propagates errors; restart is a separate command invoked only on success. The source contract is documented in [VS Code built-in commands](https://code.visualstudio.com/api/references/commands) and the [workspace-extension installation implementation](https://github.com/microsoft/vscode/blob/04c0d99f4fb0d8afe6ce4f0c58e31e183ac3e4b1/src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts#L441-L535). URI translation follows [VS Code's URI transformer](https://github.com/microsoft/vscode/blob/04c0d99f4fb0d8afe6ce4f0c58e31e183ac3e4b1/src/vs/base/common/uriTransformer.ts#L8-L45).

Automated tests cover local/SSH URI forwarding, current override rejection, explicit confirmation, errors/cancellation, no downgrade, fresh release identity, private download cleanup, archive bounds, cross-window locking and restart ordering. A self-update in a real local/Remote-SSH window also depends on VS Code's host lifecycle and platform policy; command-contract/mock coverage is not a substitute for that end-to-end qualification. Never use a user's active window or production Sessions for automated restart tests.
