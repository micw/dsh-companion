# DSH Companion Features

This document describes the currently implemented product behavior. DSH remains the authority for agents, sessions, model calls, tools, and durable history; Companion owns VS Code presentation and tab-local interaction state.

## Status legend

| Status | Meaning |
|---|---|
| `available` | Implemented and covered by the current build or tests |
| `partial` | Usable for the proof of concept, with listed limits |
| `development only` | Local F5 support, not a distributable product contract |
| `not available` | Intended scope with no current implementation |

## Overview

| Feature | Status | Current behavior |
|---|---|---|
| Global agent instructions | `available` | The Companion coding preset loads optional `~/.agents/AGENTS.md` as DSH's user-global instructions, independently of the Runtime's `DSH_HOME`; project instructions retain DSH's normal discovery rules. The injected source is labelled `~/.agents/AGENTS.md`, and subsequent changes are described as user-global rather than as a directory scope. Other files in `~/.agents` are not loaded automatically. |
| Native chat editor | `available` | **DSH: New Chat Editor** opens a draft tab; DSH creates its Session atomically with the first submitted prompt. |
| Prompt composer | `available` | Starts at one line, grows to 200 pixels, sends with Enter, and inserts newlines with Shift+Enter. Unsent drafts are discarded on window reload. |
| User images | `available` | Pasted PNG, JPEG, WebP, and GIF images can accompany text or form an image-only message. DSH durably stores accepted images, including queued messages; Companion shows them in the queue and restored transcript. |
| Text streaming | `available` | Streams Assistant text from `session/follow` and reconciles it with the durable message. |
| Markdown | `available` | Renders headings, lists, quotes, tables, links, fenced code, and closed Mermaid diagrams with raw model HTML disabled. Code blocks and Assistant answers can be copied; local file/line links open in VS Code. |
| Reasoning and Tool activity | `partial` | Groups reasoning, context injections, and paired Tool calls/results into collapsible Turn process rows; Tool presentation is generic. |
| Turn usage and timing | `available` | Shows DSH-Web-style Usage and Run-time pills plus the Turn end clock. |
| Stop | `available` | Stops the active Turn or manual compaction and attempts to clear this Session's waiting prompts. Concurrent admissions may still arrive. |
| Tab restore | `available` | Restores the same DSH session and disclosure state after the editor tab is reconstructed, then opens the transcript at its latest output. Unsent text and images are not restored. |
| Session information | `available` | A composer info panel shows the live DSH title, Session id, Companion version, supervised DSH backend build identity, and known cumulative normal-Turn cost plus coverage when DSH has accounting data; it can copy the Session id or explicitly regenerate the title through DSH's registered AI title provider. Session totals below 0.10 use three decimal places. |
| History | `available` | Opens DSH's bounded canonical Session event window and automatically requests older DSH history near the upper edge. |
| Connection recovery | `available` | Managed and source Development Runtimes use DSH's canonical Client connection, generation replacement, Session synchronization, and cursor repair after transport loss. Temporary, reversible diagnostics log only structural Client/Webview delivery and bounded scroll-jump coordinates to isolate incomplete transcripts and UI jumps. |
| DSH Web UI | `available` | **DSH: Open Web UI** opens the connected source or packaged Runtime in the default browser through a fresh authenticated launch URL; UI and API share the Runtime's loopback Web authority. |
| Development connection | `development only` | Connects to a managed DSH Web source Runtime on loopback port 3081 through an independent lifecycle supervisor ensured by the parent development task. |
| Managed Runtime | `partial` | Internal Linux packages carry an integrity-recorded patched DSH runtime, cache verified builds by runtime inputs without treating Extension client presentation changes as backend changes, install immutable runtime identities under VS Code global storage, retain one rollback runtime, and reuse a matching independent supervisor across frontend-only Extension updates; DSH-owned idle eligibility remains unavailable. |
| Provider/model selection | `available` | Selects DSH catalog models and model-specific reasoning effort from the composer; the selected label includes the adapter-owned provider display name, while DSH owns validation, persistence, and defaults. |
| Session permissions | `available` | Selects a DSH-owned permission preset from the composer before or after Session creation, restores started Sessions from their durable projection, and requires an explicit modal warning before enabling `danger-full-access`. |
| Provider onboarding | `available` | Fresh Companion profiles start with no configured provider instances. DSH Web and the native provider manager list installed families separately, create and rename multiple stable OpenRouter instances, replace credentials, enable or disable routes, and delete instances through canonical DSH operations without exposing stored credentials. |
| External provider plugins | `available` | Source and packaged Managed Runtime profiles load the multi-instance OpenRouter family plus Codex Wrapper Advanced and Claude Wrapper Advanced. Generic pi-ai/OpenAI and native DeepSeek providers are not loaded; dedicated families remain future work, while wrapper services, deployment, authentication, and secrets remain external. |
| Agent preset | `available` | Companion exposes one system preset based on DSH `standard`, with fresh spawn delegation and Goals retained and fork-based delegation omitted; Sessions that recorded the retired `standard` id resume through a roster-hidden fallback. |
| Model-initiated Session title | `available` | A root-Agent-only `set_session_title` Tool proposes a title for its own live Session only after a meaningful topic shift; DSH accepts it with provider identity and the logged main-model route, while protecting manual user titles. The current canonical title enters a change-suppressed user-role runtime-context snapshot rather than the system-prompt prefix. |
| Fork-based Subagents | `not available` | The Companion preset omits `subagent_fork` to prevent unbudgeted copies of Parent history; fresh spawn delegation and Goals remain unchanged. |
| One-shot Tool approvals | `available` | VS Code can allow one Tool request once or reject it. Pending prompts belong to the requesting Session; DSH records the outcome in its Turn, and other windows show the same result. This does not change the standing Session permission. |
| User questions | `not available` | The Companion preset does not expose `ask_user_question` until a separate VS Code answerer exists. |
| Queue and steering | `available` | Queues separate prompts for later Turns, including while manual compaction runs after DSH records its start. New and waiting queued prompts can steer into a running Turn. A leading `!` steers the draft without sending the marker, starts a new Turn when idle, and queues during manual compaction. Waiting prompts can be removed, and the last queued text-and-image message can be returned to the composer without retaining its queue position. |
| Session browser | `partial` | A native VS Code sidebar lists DSH root Sessions for the current workspace roots by default; Search all workspaces includes other paths with a location label. Opening another path prompts before focusing an existing matching VS Code window or opening one and handing off the Session id. Search includes question and answer content; rename, archive, delete, and fork controls are not available. |
| Chat tab title and activity | `available` | Started editor tabs follow DSH Session-list title changes; a colored tab dot distinguishes running, unseen success, unseen error, and seen results, restoring the seen watermark per Session. |
| Session Changes | `not available` | Native SCM projection, persistent Edit Ledger, Dirty-buffer protection, review, and guarded revert remain planned. |
| Native terminals | `not available` | No VS Code-backed DSH `TerminalBackend` exists yet. |
| Context meter | `available` | Shows DSH-projected next-request pressure and route capacity in a composer ring, with manual DSH compaction when the Session provides `/compact`. |
| Monetary cost | `partial` | The patched DSH Runtime persists provider-neutral reported, estimated, and virtual call or complete-Turn accounting, derives Turn and cumulative Session sums without converting currencies, and projects them to the VS Code UI. OpenRouter records response-reported USD cost for each accounted call, while Claude Wrapper Advanced emits virtual USD list-price equivalents with explicit coverage. |

## Chat and session behavior

**DSH: New Chat Editor** always opens a new draft tab rooted at the first VS Code workspace folder, but it does not create or list a DSH Session until the first prompt is submitted. Unsent text and images remain tab-local until submission; a preselected provider, model, reasoning effort, or permission preset remains presentation state. The first submission creates the Session, applies those remembered selections through DSH, opens the canonical streams, and then submits the prompt. Closing an unstarted tab therefore leaves no DSH Session. The DSH Companion sidebar shows an explicit connecting, refreshing, ready-empty, or error state while it follows DSH's live canonical Session-list order; connection, refresh, and search work also uses VS Code's native view progress line. It displays root Session titles, relative activity times with the exact date and Session details on hover, running state, completion reminders, and the currently active Companion tab, and refreshes after connected editor activity as well as on manual request. Its settings action focuses an existing Companion editor and opens the provider manager, or opens an unstarted draft editor first when none exists. Selecting a listed Session focuses its existing editor when open or creates an editor bound to that exact Session id when closed. The sidebar compares the Session working directory with exact VS Code workspace roots, including every root in a multi-root window. By default it shows only matching Sessions; Search all workspaces also shows other paths with their folder name and full path on hover. A Session from another path requires confirmation before opening its directory in VS Code (or focusing its existing window) and selecting the same Session there; a short-lived handoff is consumed by both running and newly activated windows, without copying Session state; a Session without a known path can only be opened here after a warning. The persistent sidebar search field runs a cancellable, 200-millisecond-debounced query that combines immediate case-insensitive title matches with DSH's bounded full-text search over current `user/message` and `assistant/message` content; it displays the matching snippet as results arrive and does not activate Sessions while searching. The Companion profile enables DSH's separate durable SQLite-derived search index and defers opening it until the first query. Subagent Sessions remain excluded from listing and search results until Companion can preserve their parent-derived navigation address. Restoring an existing started editor tab reuses its saved Session id and reloads transcript content from DSH; Companion does not persist a second transcript. Closing a started tab only closes the DSH client stream and does not delete the DSH Session.

The tab-local state contains the Session id, current scroll position, and disclosure choices; it does not store unsent text or image bytes. Started tab titles follow DSH's canonical Session-list `displayTitle`: the first-message fallback is displayed until DSH commits a generated title. The DSH base profile requests an auxiliary first-prompt title once for a new root Session; failure retains the fallback, and later prompts or forks do not automatically retitle. Session Information can explicitly refresh the title using DSH's current registered provider and eligible human prompts, including for a fork; this deliberate action also replaces a manually pinned title. The Companion preset includes `set_session_title` for the active root Agent. The Tool uses DSH's bounded proposal operation instead of user rename, cannot override a manually pinned title, and records the Companion tool provider identity alongside the logged main model route. DSH injects the current canonical title as a change-suppressed, durable user-role runtime-context snapshot near the request tail; title updates do not rewrite the cached system-prompt prefix. The bundled Codex and Claude wrapper adapters admit that auxiliary request but cannot enforce its output-token cap at the wire level; DSH still validates the returned title. Each tab shows a blue dot while running, green for an unseen completed Turn, red for an unseen failed Turn, and gray once an idle result has been viewed in an active, visible tab. The last viewed Turn-end time is stored in VS Code global state per Session for tab restore; the Turn outcome and title are reconstructed from DSH, not duplicated in tab state. A reconstructed tab deliberately opens at the latest output instead of applying its stored pixel position. Stable keys identify Turn, reasoning, Tool, context, Usage, Cost, and timing disclosures, so each row can retain its open state independently. This state is presentation-only and never enters the DSH session log.

History remains a contiguous DSH-owned event window. The first attached Client snapshot always replays its full retained window, even when the snapshot's `change` describes only the last append, prepend, or Assistant settlement. A live Assistant settlement without a durable entry removes only the abandoned attempt's transient text, not the transcript; a later committed answer appears once in both live and restored views. Initial loading extends a bounded Follow snapshot only when it contains no human prompt, then keeps the complete initial tail attached while older pages prepend and returns a reconstructed tab to the latest output. Approaching the upper edge after a user scroll loads additional `session/page` records through the next older human prompt, merges a Turn split across page boundaries by its stable DSH Turn identity, and preserves the visible scroll position. DSH's current Session snapshot is the sole authority for whether work is running; a restored Turn with committed events but no `turn/end` is retained and marked interrupted when the Session is idle.

The composer model picker searches the provider-grouped `session/modelCatalog` and follows the Session's durable `modelSelection` projection. Its selected label uses `<provider name> / <model name>` from that catalog; the Companion wrapper adapters advertise the concise names `Claude` and `Codex`, while built-in providers retain their DSH names. Models expose only the reasoning efforts and display metadata reported by their DSH adapter. Provider default remains a distinct choice even when the catalog names its current effective default, so selecting it omits `reasoningEffort` and continues to follow later provider-default changes. Selecting another model also lets DSH resolve that model's default instead of carrying effort across routes. Selection is unavailable during a running Turn. With the current DSH operation, a Session selection also becomes the default for future Sessions.

The composer permission selector derives its options and initial draft value from DSH's permission settings schema, follows the durable `permissions` projection after Session creation, and executes a changed preset through DSH's canonical `/permission` command before the draft's first prompt is submitted. Permission options, custom labels, descriptions, and the current value remain DSH-owned; conventional built-in ids use DSH Web's `Read Only`, `Workspace Write`, and `Full access` display labels, while `custom` can be displayed but not selected. The control is locked during active Agent or compaction work. Enabling the built-in `danger-full-access` preset requires a modal risk confirmation because it disables filesystem sandboxing for the Session; returning to `workspace-write` does not. A restored tab receives the Session's last logged preset, while a new draft starts from DSH's configured default. This selector changes standing Session policy; one-shot Tool approvals do not.

The source and packaged profiles start without an active model route on a clean data home. Installed provider families and configured instances are separate DSH projections: OpenRouter appears as an Add action, while only saved instances appear as rows and publish stable routes after their credential and dynamic catalog validate. OpenRouter supports multiple independently named instances, each with its own credential, route, catalog LKG, account state, model policy, and lifecycle. Renaming preserves route identity; deletion retires the instance identity so historical Sessions never bind to another account. The generic pi-ai/OpenAI and native DeepSeek plugins are disabled in Companion composition and contribute neither routes nor dormant rows. DSH Web's Models page and the gear in the VS Code model picker create, edit, test, enable, disable, and delete instances through DSH's canonical operations; both surfaces enforce the server-reported family limit and show credential status without reading secrets back. Newly discovered OpenRouter models inherit the family policy and default to disabled until exact models or the catalog are enabled; route-specific overrides then take precedence. Wrapper providers retain their existing singleton settings until they migrate to the family API. Generic Companion plugins retain validated last-known-good dynamic catalogs in DSH storage, expose process-local account and allowance snapshots, and store only user model-policy intent in DSH Settings. For the selected provider, the VS Code composer shows a compact usage trigger beside Context and a refreshable allowance panel with absolute spending-cap limit, used and remaining USD values, percentages, reset countdowns, warning thresholds, and a time-position marker. OpenRouter delegates request and streaming translation to DSH's pi-ai adapter library without loading the generic pi-ai plugin; its terminal SSE `usage.cost` becomes provider-reported call accounting and DSH aggregates accounted calls into complete normal-Turn and Session totals. Dynamic catalogs are never materialized into `settings.yaml`; running calls retain the immutable adapter and catalog generation captured at admission. Packaging embeds only the independently maintained provider packages; wrapper services and all secrets remain external.

The context ring appears only when DSH provides both pressure and route capacity. Its numerator comes from the `contextPressure` projection, while its denominator follows the selected route's adapter-validated capacity from `session/modelCatalog`; model switches therefore refresh the percentage without waiting for another request. It prefers projected next-request tokens over the latest provider sample, caps only the visual ring at 100 percent, and exposes the approximate size and limit on hover, focus, or click. The Compact action appears only when the Session command catalog provides `/compact`; it executes that DSH command with the composer's current provider/model selection while the Agent is idle and displays its canonical result without changing context state optimistically. Durable `compaction/*` events produce a running and settled transcript activity row. While compaction runs, the prompt and model controls are locked and Stop remains available through `session.cancel`.

## Transcript presentation

User prompts use a compact VS Code-themed card. Live output follows the bottom until the user scrolls away; wheel, touch, keyboard, scrollbar, and text-selection gestures pause following before the next streamed update can override them. A downward gesture that reaches the bottom, including its trailing momentum, the latest-output button, or another submitted prompt resumes following; layout-driven scroll events without a recent downward gesture do not. When a growing transcript first becomes scrollable, the Webview refreshes Chromium's scroll bounds without changing the reading position. During streaming, Assistant Markdown updates are coalesced, unchanged nodes remain mounted, and selections within an answer are restored after changed Markdown renders; the transcript disables automatic browser scroll anchoring and retains the reader's position while follow is paused. When no prompt is visible, the nearest prompt fully above the viewport is pinned at the top; if any later prompt remains visible, the earlier prompt stays unpinned until that later prompt has scrolled away. A jump button returns to the original prompt. Assistant text uses `markdown-it`; raw model HTML is escaped, unsupported URI schemes are rejected, and HTTP or HTTPS links open through VS Code. Local Markdown links and bare paths open on explicit click at an optional line; relative paths use the DSH Session directory, absolute and outside-Workspace paths are allowed, and files inside a Remote-SSH workspace retain its URI authority. Assistant progress messages and durable compaction activity split the visible Turn process into chronological disclosures: earlier Reasoning and Tool rows stay above the boundary, and later rows follow it, including when text and a Tool call share one Step. Recoverable provider-attempt failures do not appear as final transcript errors; an error is shown when DSH ends the Turn with one. DSH still owns a single Turn. Reasoning, context injections, Tool calls, and Tool results appear inside disclosures inspired by DSH Web. Each title summarizes only its segment's Reasoning, Tool Calls, and Context Injections, while a Turn without process rows shows its measured `Thought for …` duration as a non-interactive row instead of an empty disclosure.

Reasoning-token status belongs to its DSH Turn and Step. A final count arriving after live Assistant text updates the process disclosure before that answer, rather than creating a later Thinking block; a different Step can still start a later disclosure. Restore reconstructs the same order from durable events.

File-link hover shows the target path and optional line or inclusive GitHub-style line range (`#L117-L122`). The range is removed from the filesystem path and selected in the opened document. VS Code's native right-click menu opens file links, opens them beside the chat, or copies their target or resolved absolute path; clicking the link opens it directly. External HTTP links have native open and copy actions.

HTTP and HTTPS Markdown links invoke only VS Code's external-open operation. Their Webview anchors do not navigate separately, so one click cannot also trigger the Webview's native link handler.

Tool rows show a generic summary, raw arguments, and text result. A delayed result for a Tool call outside the retained transcript does not create an empty Turn; a result for a visible call updates that row. One-shot approvals appear on the relevant Tool row; completed decisions remain visible after restore, while stale prompts cannot be answered. Specialized file previews, code-copy controls, syntax highlighting, Mermaid, and presenter-specific cards are not available.

## Turn information

Companion derives one completed-Turn summary from DSH's durable Turn, Step, request, Assistant, usage, and accounting data. Usage aggregates recorded attempts and displays exact total, uncached input, optional cached input and cache write, output, provider/model routes, and cache-hit percentage. Reasoning is displayed only when its aggregate is greater than zero. When accounting exists, a separate Cost pill sums each currency and retains reported, estimated, and virtual kinds plus route, source, tariff, and bucket details; estimated totals use `~`, virtual totals identify their equivalent value, mixed kinds use a sum marker, and incomplete Session coverage identifies the displayed amount as a known subtotal. Context occupancy is deliberately excluded.

The Session Information panel shows one compact known sum per currency with an expandable reported, estimated, and virtual breakdown. Projection coverage counts accounted and unaccounted model Turns; a partial sum is marked as known rather than presented as complete spend. It folds only normal-Turn model settlements in that DSH Session; Session-title, compaction, and child-Session calls are not included.

The timing panel shows Turn wall time and, when the event sequence provides them, first-Step time to first token and aggregate decode throughput. The clock uses `turn/end.time`. Usage, Cost, and timing panels preserve their open state with the tab, while opening another panel, clicking outside, or pressing Escape closes the active transient panel.

## Development connection

The source development connection is fixed to `http://127.0.0.1:3081`, and the installed Managed Runtime binds its own loopback origin (`http://127.0.0.1:3082`), so packaged activation never collides with a DSH already running on the development origin; both require a managed source or packaged Runtime. The parent development task starts or reuses an independent lifecycle-only source supervisor, while each activated Extension Host renews a private client lease and obtains the process launch URL through the supervisor without persisting its token in the rendezvous. The authenticated supervisor endpoint returns a compact DSH backend build identity: source development includes the checkout commit and dirty state, while packaged Runtimes include the pinned upstream commit and patch-set digest. A retained older supervisor can report this field as unavailable without preventing Session use. The extension exchanges that URL for an authority-bound cookie and retains the cookie in VS Code Secret Storage. **DSH: Open Web UI** obtains a separate fresh launch URL for the same authority; the UI root, HTTP API, and multiplexed WebSocket share that loopback server and reject unauthenticated requests. Session streams, queue state, projections, paging, and recovery use DSH's Node Client assembly. Companion has no manual URL/token or no-supervisor connection mode. Debug restarts reuse the source Runtime; running **DSH Companion: stop runtime** or **DSH: Stop Managed Runtime** ends its process tree explicitly.

Internal Linux VSIX packages include a runtime built from the pinned official DSH commit plus an integrity-checked downstream patch series. On first activation the Extension verifies the closed payload, installs it under `globalStorageUri/runtime/versions/<companion-version>-linux-x64`, starts its supervisor against the separate persistent `dsh-home`, and records active and rollback versions only after readiness. The supervisor publishes its source or installed runtime identity. An Extension Development Host reuses the explicit source owner; an installed Extension replaces any source or mismatched installed owner with its packaged runtime under the shared lifecycle lock. If an Extension Host dies while holding the runtime-manager lock, a later window checks the recorded process owner and reclaims the abandoned lock before retrying; live owners continue to serialize installation. Runtime installation never modifies the Extension directory, and cleanup retains DSH data. DSH-reported idle eligibility, automatic idle shutdown, robust crash recovery, signed public builds, and External DSH mode remain unavailable.
